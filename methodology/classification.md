# 分類基準とコーディング手順

バージョン 1.2.0

## 構成

| 層 | 内容 | どこに書くか |
|---|---|---|
| 共通フラグ | どのチャンネルでも判定できる内容の特徴 | 本書、規則は `analyze/auto_labels.py` |
| テーマ体系 | チャンネル・ジャンルごとに作る | `docs/<slug>-codebook.md`、設定の `[themes]` |
| 固有フラグ | そのチャンネルの仮説に必要な特徴 | `docs/<slug>-codebook.md`、設定の `[flags]` |

## 共通フラグ（v1.1.0）

| 列 | 定義 | 規則（タイトルのみ、`auto_labels.py`） |
|---|---|---|
| `japan_angle` | 視聴者の国（日本）・日本人・日本企業との関係をタイトルで明示している | 日本・日銀・邦人・国産・円安・日本企業名などを含む |
| `intl_compare` | 国同士の比較。次のどちらか | `intl_ranking_rule` または `intl_pair_rule` |
| 〃 多国間ランキング型 | 3か国以上の順位・コンテスト・レース・大会 | ランキング・コンテスト・レース・大会・N位・世界一・どの国 など |
| 〃 2か国比較型 | 2つの国（または国を代表する企業）を並べ、比較の語を含む | 国名・企業名が2つ以上 ＋ より・対・vs・比較・違・倍・追いつく・抜く など |
| `counterintuitive` | 通説・直感と逆の結論を示す | 実は・じゃない・だから何・マシ・意外・勘違い など（手作業との一致 κ0.42、要改善） |
| `anxiety` | 危機・損失・脅威を前面に出す | 危機・崩壊・ヤバ・地獄・破綻・暴落 など |
| `timely` | 特定の直近の出来事（発表・事件・上場・決算）を起点にする | 速報・上場・逮捕・発表・判明・N月 など（κ0.23、定義の見直し中） |

- `japan_angle` の「日本」は視聴者の国を指す。日本以外の視聴者向けチャンネルでは、設定 `[auto_labels]`（今後追加）または固有フラグで国を置き換える
- 規則は手作業の判定を再現するための比較基準で、手作業の代わりではない。規則と手作業の κ が 0.6 未満のフラグは、結論の根拠として単独で使わない

## テーマ体系の作り方

URLからの自動調査では、再生数を参照せずタイトルと概要欄の反復文字列から暫定テーマを作る
結果は `labels_auto.csv` と `theme_model.json` に保存し、人手検証済みとは扱わない
手作業の `labels_manual.csv` がある場合は常にそちらを優先する

1. 再生数を伏せたシート（`ycanalysis.annotate <slug> export`）でタイトルを全件読む
2. 最初の50本程度から候補テーマを作り、1本1テーマで判定できるよう定義と境界の規則を書く（例：経済と国際情勢が重なる場合は「タイトルが問うている主語」で決める）
3. 雑談・告知・音楽など、内容比較の対象外にするテーマを決め、設定 `exclude_themes` に書く
4. 全件を判定し、`data/<slug>/annotations/labels_manual.csv` に保存（列：`video_id, title, theme, <フラグ...>`）
5. 未分類（どのテーマにも入らない）が5%を超えたら体系を見直す

## 一致率の確認（再現性）

- 同じシートを、別のコーダー（別の人、または判定基準だけを渡した別の AI セッション）が再判定する
- `ycanalysis.annotate <slug> agreement <再判定CSV>` で列ごとの κ を出す
- 目安：κ ≥ 0.8 ほぼ一致、0.6〜0.8 実質的に一致、0.4〜0.6 中程度、0.4 未満は基準を見直す
- 再生数を見た後に判定・基準変更をした項目は、そのことを `docs/<slug>-codebook.md` に書く

## 構成のコーディング（工程8）

`docs/overseas-y-papa-codebook.md` の `phase3_coding.csv` の列定義を共通の出発点にする
自動検出（`analyze/phase3.py` の定型句の位置）と手作業の判定を併記し、両者が食い違う項目は結論に使わない
