# 指示書：YouTubeチャンネル分析リポジトリの構築と「海外Yパパ」の成長要因調査

> 共通原則は [AGENTS.md](../AGENTS.md) を参照
> 本書は海外Yパパ固有の調査要件
> 受領日：2026-10-19

## 1. 目的

YouTubeチャンネルの成長要因を体系的に分析するための専用リポジトリを構築し、最初の調査対象として「海外Yパパ」を分析する。

対象チャンネル：https://www.youtube.com/@海外Yパパ

目標は、チャンネルが成長した要因を、動画のテーマ・構成・長さ・タイトル・サムネイル・投稿戦略などの観点から明らかにすることである。

さらに、調査結果から、他のYouTubeチャンネルでも応用可能な制作手法を抽出する。

単なる人気動画の特徴の列挙ではなく、定量分析と定性分析を組み合わせ、仮説を検証する。

## 2. リポジトリの作成

### 2.1 基本方針

`youtube-channel-analysis` という専用のGitリポジトリを新規作成する。

このリポジトリは、特定のチャンネル専用ではなく、今後さまざまなYouTubeチャンネルを分析するための共通基盤とする。

ただし、今回の海外Yパパの調査に必要な機能から実装し、過剰な汎用化は避ける。

### 2.2 ディレクトリ構成

以下を基本構成とする。

```text
youtube-channel-analysis/
├── README.md
├── AGENTS.md
├── .gitignore
├── docs/
│   └── overseas-y-papa-analysis.md
├── src/
│   ├── collect/              # データ収集
│   ├── analyze/              # 集計・分析
│   └── visualize/            # グラフ作成
├── data/
│   └── overseas-y-papa/
│       ├── raw/              # 取得した元データ
│       └── processed/        # 分析用に加工したデータ
├── reports/
│   └── overseas-y-papa/
│       ├── charts/
│       ├── thumbnails/
│       └── FINAL_REPORT.md
└── tests/
```

必要に応じて構成を調整してよい。

ただし、**共通の分析コードと、チャンネル固有のデータ・分析結果を明確に分離すること。**

### 2.3 AGENTS.md

リポジトリ直下に `AGENTS.md` を作成する。

ここには、特定チャンネルに依存しない、すべての調査に共通する原則を記述する。

主な内容：

- 調査は再現可能な方法で実施する。
- 定量分析と定性分析を組み合わせる。
- 成功事例だけでなく失敗事例も分析する。
- 事実・推論・仮説を区別する。
- 相関関係から安易に因果関係を断定しない。
- 取得データの出典と取得日時を記録する。
- 取得できないデータを創作しない。
- 収集処理と分析処理を分離する。
- 分析コードは可能な限り再利用可能にする。
- 調査結果に反する事例も報告する。
- 認証情報をリポジトリに含めない。
- 各サービスの利用規約と権利関係を遵守する。

Claude Code、Codexなど、使用するAIエージェントに依存しない記述とする。

### 2.4 調査指示書

海外Yパパ固有の調査要件は、`docs/overseas-y-papa-analysis.md` に記載する。

`AGENTS.md` に調査対象固有の情報を重複して書かない。

## 3. Phase 1：全動画のデータ収集

公開されている全動画を原則として調査対象とする。

### 3.1 収集項目

**動画の基本情報**
- 動画ID・URL
- タイトル
- 説明文
- 公開日時
- 動画の長さ
- 通常動画／Shorts／ライブ配信の区分
- サムネイル画像

**動画の実績**
- 再生数
- 高評価数
- コメント数
- 公開からの経過日数
- 公開後の再生数推移（取得できる場合）

**チャンネル情報**
- 登録者数
- 総再生数
- 公開動画数
- チャンネル開設日
- 登録者数・再生数の過去の推移（取得できる場合）

### 3.2 収集方法

YouTube Data APIなどの公式手段を優先する。

必要に応じて、外部の統計サイトや公開情報を用いて補完する。

公式APIで取得できない情報については、取得可能な代替手段を調査する。

公開データから取得できない視聴維持率・クリック率・登録転換率などを推測で補完しない。

データの出典、取得日時、取得方法を記録する。

### 3.3 データ管理

収集した元データは `data/overseas-y-papa/raw/` に保存する。

加工・分類したデータは `processed/` に保存し、元データを上書きしない。

収集スクリプトを保存し、同じ処理を再実行できるようにする。

APIの認証情報や大量の一時ファイル、不要なバイナリファイルはGitの管理対象から除外する。

## 4. Phase 2：定量分析

### 4.1 成長過程

以下を時系列で分析する。

- 登録者数の推移
- 総再生数の推移
- 月別の投稿本数
- 動画ごとの再生実績
- 突出して再生された動画の公開時期

登録者数が急増した期間を特定し、その前後に公開された動画や外部ニュースとの関係を調査する。

過去の登録者数などが取得できない場合は、分析可能な範囲を明示する。

### 4.2 テーマ

動画のテーマを分類し、再生実績との関係を分析する。

分類例：

- 国際情勢・政治
- 経済・ビジネス
- 科学・技術・AI
- 社会問題
- 歴史・文化
- その他

実際の内容に合わせて分類体系を調整する。

テーマそのものに加えて、以下の特徴も検証する。

- 時事性
- 意外性
- 視聴者との関連性
- 常識に反する結論
- 不安や好奇心の喚起

### 4.3 タイトル

次の要素と再生実績の関係を分析する。

- 文字数
- 疑問形・断定形・説明形
- 数字の使用
- 固有名詞の使用
- 結論の先出し
- 逆説的表現
- 危機感・驚き・好奇心の喚起

### 4.4 サムネイル

サムネイルを収集し、以下の要素を比較する。

- 文字数・文字の大きさ
- 配色
- 写真・イラスト・図解の使い方
- 人物や顔の有無
- 情報密度
- タイトルとの役割分担

代表的なサムネイルを一覧化し、視覚的に比較できるようにする。

### 4.5 動画の長さ

以下を分析する。

- 動画尺の分布
- 長さ別の再生実績
- テーマ別の平均動画尺
- 動画尺の時系列変化

公開時期が異なる動画を単純な累計再生数だけで比較しない。

公開後7日間・30日間の再生数など、同一条件で比較可能なデータが取得できる場合は優先する。

取得できない場合は、公開時期を考慮した比較方法を検討し、その限界を記述する。

通常動画とShortsは原則として分離して分析する。

### 4.6 投稿戦略

- 投稿頻度
- 投稿曜日・時間帯
- 連続投稿
- シリーズ化
- テーマの時系列変化

これらと再生実績との関係を検証する。

## 5. Phase 3：代表動画の内容分析

Phase 2の結果から、代表的な動画を36本程度選定する。

原則として以下の3群から各12本を抽出する。

1. 高再生実績の動画
2. 標準的な再生実績の動画
3. 低再生実績の動画

可能な限り公開時期やテーマの偏りを抑える。

### 5.1 構成

動画の映像・音声・文字起こしを用いて、以下を分析する。

**冒頭**
- 本題に入るまでの時間
- 問題提起の方法
- 結論提示のタイミング
- 視聴する動機の形成

**本編**
- 論理構成
- 主張と根拠の提示順序
- データや具体例の使い方
- 話題の転換
- 情報密度

**終盤**
- 結論の示し方
- まとめの長さ
- 次の動画への誘導
- 登録・評価の呼びかけ

動画ごとに構成のタイムラインを作成する。

### 5.2 映像表現

- 図解・イラストの使用
- 写真・ニュース映像の使用
- 画面切り替えの頻度
- アニメーション
- 字幕・テロップ
- ナレーションと映像の対応関係

文字起こしだけで映像内容を推定せず、実際の映像を確認する。

### 5.3 ナレーション

- 話速
- 語り口
- 専門用語の使用
- ユーモア・皮肉
- 主観と客観の使い分け
- 情報密度
- 聞き流しへの適性

### 5.4 成功動画と低実績動画の比較

高実績動画に共通する特徴が、低実績動画にも存在するか検証する。

単に成功動画に存在するだけの特徴を成功要因とみなさない。

## 6. Phase 4：類似チャンネルとの比較

ジャンル・動画形式・視聴者層が近いチャンネルを2〜3件選定する。

以下を比較する。

- テーマ
- 動画尺
- 投稿頻度
- タイトル・サムネイル
- 構成
- 映像表現
- ナレーション
- 再生実績
- 成長過程

ジャンル全体に共通する特徴と、海外Yパパ固有の特徴を区別する。

比較対象の選定根拠を明記する。

## 7. Phase 5：成長要因の仮説検証

分析結果から、成長に寄与したと考えられる要因を抽出する。

各仮説について、以下を整理する。

1. 仮説
2. 支持するデータ・事例
3. 反証となるデータ・事例
4. 代替説明
5. 確信度
6. 他チャンネルでの再現可能性

特に、次の4つの段階で成長要因を整理する。

**発見される要因**

検索需要、時事性、SNSでの拡散など。

**クリックされる要因**

テーマ、タイトル、サムネイルなど。

**視聴を継続させる要因**

構成、ナレーション、映像表現など。

**再訪・登録につながる要因**

一貫したテーマ、信頼形成、シリーズ化など。

非公開のYouTube Analytics指標が必要な仮説については、公開データのみで検証可能な範囲を明示する。

## 8. 成果物

最終的に、以下の報告書を作成する。

`reports/overseas-y-papa/FINAL_REPORT.md`

報告書の構成：

1. 調査概要と主要な結論
2. チャンネルの成長過程
3. テーマ・タイトル・サムネイルの分析
4. 動画尺・投稿戦略の分析
5. 動画構成・映像表現・ナレーションの分析
6. 類似チャンネルとの比較
7. 成長要因の仮説検証
8. 他チャンネルでも再現可能な制作手法
9. 分析の限界と未検証事項

可能な限り、グラフ、比較表、サムネイル一覧、動画構成のタイムラインなどを用いて視覚的に説明する。

各結論には、出典や具体的な動画URL、根拠となる数値を付ける。

## 9. 技術的な実装方針

### 9.1 技術スタック

データ収集・集計・可視化に適した技術を選定する。

Python、YouTube Data API、pandasなどを候補とするが、特定の技術に固執しない。

選定理由をREADMEに記録する。

### 9.2 再利用可能性

チャンネルIDなどの設定を変更することで、同じ収集・集計処理を別のチャンネルにも適用できる設計とする。

ただし、将来の用途を推測して大規模なフレームワークを先行開発しない。

### 9.3 再現性

- 依存ライブラリとバージョンを管理する。
- データ収集手順をREADMEに記載する。
- 同じデータから同じ分析結果を再生成できるようにする。
- 分析処理の主要部分に自動テストを用意する。
- データ収集時点の情報を残す。
- 取得済みデータを不必要に上書きしない。

### 9.4 セキュリティ・権利関係

- APIキーをコードに埋め込まない。
- `.env` などの機密ファイルをGit管理から除外する。
- 動画・音声・サムネイルの取得と保存は利用条件・著作権に配慮する。
- 調査に必要のない大量の映像データを蓄積しない。
- 外部サービスに過剰なアクセスを行わない。
- GitHubなどのリモートリポジトリへの公開は、保存データや認証情報を確認したうえで別途判断する。

## 10. 実行順序

以下の順序で作業する。

1. 専用リポジトリを作成する。
2. `AGENTS.md` と `README.md` を整備する。
3. 本指示書を `docs/overseas-y-papa-analysis.md` に保存する。
4. Phase 1のデータ収集を実装・実行する。
5. Phase 2の定量分析を実施する。
6. 分析結果に基づきPhase 3の対象動画を選定する。
7. Phase 3の内容分析を行う。
8. Phase 4の類似チャンネル比較を行う。
9. Phase 5の仮説検証を行う。
10. 最終報告書を作成する。

各段階で、分析方法・結果・制約・未完了事項をファイルに記録する。

外部サービスの認証設定など、人間による操作が必要な場合は、その内容を具体的に報告する。

それ以外の処理は可能な限り自律的に進める。

## 11. 最終的な到達目標

調査は、次の問いに回答できる状態をもって完了とする。

**「海外Yパパは、なぜ成長したのか。そのうち、どの要因が他のYouTubeチャンネルにも再現可能なのか。」**

成功要因を単に推測するのではなく、データに基づいて仮説を支持・棄却し、再現可能な制作・運営手法として整理すること。

なお、今回の調査で構築した分析基盤は、今後別のチャンネルを調査する際にも再利用できる状態を目指す。
